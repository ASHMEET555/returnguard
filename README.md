# ReturnGuard — Build Pack (PayPal + AI Hackathon edition)

AI-powered return-abuse risk detection and dispute evidence for e-commerce merchants, with a real PayPal sandbox payment path and an AG Grid investigation console.

Hackathon: **Build What's Next with PayPal and AI**. The one hard rule: the project must meaningfully use PayPal **and** AI.

Build **in order**. Do not skip Phase C. Held-out metrics are the bar, and no sponsor work starts before they are green.

## What changed from the original build pack

- Added a PayPal payment path (Orders API, authorize/capture, webhooks) alongside the original COD/RTO detector.
- Added a PayPal Disputes API path for evidence submission, gated behind human approval and a sandbox-only flag.
- Added an AG Grid investigation console as the primary merchant UI.
- Added an LLM assistant that explains ML output. It does not decide risk.
- Kept the detector, rules, rings, metrics, shadow-first stance and defense-only pledge.

Full list of accepted, modified and rejected recommendations is in [01-brief.md](01-brief.md#plan-review-decisions).

## Stack (locked)

- Backend: Python FastAPI, PostgreSQL
- ML: scikit-learn (logistic baseline), XGBoost (primary)
- Payments: PayPal REST APIs in **sandbox** (Orders, Webhooks, Disputes)
- LLM: Gemini or OpenAI API, used for explanations and drafts only
- Frontend: Next.js + React, AG Grid Community (see [02-architecture.md](02-architecture.md#ag-grid-licensing-and-scope))

## Defense pledge (updated)

- Risk detection is shadow-first. Soft actions only: allow, log, step-up verification, prepaid preference, manual review.
- Never auto-cancel, void or reject a payment or order.
- Dispute evidence is generated by the AI and reviewed by a human. Submission to PayPal happens only after an explicit human approve, and only in sandbox for this build.
- Payment capture and evidence submission are separate operations. Every action writes an audit row.
- No offense-capable tooling. No automated dispute filing. No scraping of other merchants.
